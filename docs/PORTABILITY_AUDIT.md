## Part 3: text, encodings and line endings
- No file read or write in the project passes CharacterEncoding; everything relies on the platform default. On the Mac $CharacterEncoding is UTF8.
- Measured on the Mac: string literals in the script given to `wolframscript -file` are decoded as Latin-1, while files loaded with Get decode as UTF-8. Evidence: henon/main.wl:45 STEMHeading["Hénon Map"] prints `=== HÃ©non Map ===` (bytes c3 83 c2 a9) in all three henon modes; relativity main prints `Time stretch: 4.Ã\x97` for `×`; a probe script printed `HÃ©non RÃ¶ssler Î´ Î»`. The same "Hénon" in henon/src/speech.wl (loaded with Get) prints correctly (c3 a9). Of the 109 regression-sweep logs, 4 contain such mojibake (henon x3, relativity chirp). This also explains why a henon test comparing a literal "Hénon" in the test script failed earlier.
- On Windows the default $CharacterEncoding is not UTF-8 (VM), so files loaded with Get may mis-decode too, which would garble every non-ASCII literal, including narration text.
- Non-ASCII characters inside string literals (not comments) in 63 .wl files: the em dash in about 60 (mostly error and console messages); é in demo.wl, henon/main.wl, henon/src/animate.wl, henon/src/output.wl, henon/src/speech.wl; relativity/src/model.wl (² ̃ Δ τ φ ₀ → ☉), relativity/main.wl (× ☉), relativity/src/sonify.wl (☉); signal/src/animate.wl (₀ ₁); pendulum/src/sonify.wl (−); asteroids/src/animate.wl (–).
- Named characters in strings (\[LongDash] 11 files, \[Mu] 5, \[ODoubleDot] 3, \[Times] 3, \[RightArrow] 3, \[CapitalOmega] 3, \[Lambda] 2, \[EAcute] 2, and others, 23 files): ASCII-safe in the source, but they reach the console and CSV as Unicode.
- Console on Windows: wolframscript writes UTF-8 (on the Mac); the default Windows console code page (437/850/1252) shows it garbled unless `chcp 65001` is set (VM). Affects em dashes, λ, δ, ☉ and Hénon/Rössler in console lines; Rössler appears only in comments and docs, not in output.
- Narration with non-ASCII: only henon ("Hénon") among the narrated apps; dynamical narration is ASCII.
- Config JSON: stem-core/config.wl:109 Import[path, "JSON"] and :161 ImportString[..., "RawJSON"]; henon/config.json contains "Hénon" in its description. A config.json saved by Windows Notepad with a BOM or in ANSI is untested (VM).
- CSV: stem-core/src/export.wl:19 Export[filePath, rows, "CSV"], no encoding option; CSV content is almost all ASCII (labels such as event names).
- Text exports: demo.wl:774 (demo-report.md) and :997 (demo/README.md), demo_html.wl:1793 and demo_outreach.wl:770 (HTML) use Export[..., "Text"] with no encoding; they contain em dashes and named characters (\[LongDash]).
- Line endings: no .gitattributes; Git for Windows defaults to core.autocrlf=true, so .wl/.json/.md check out with CRLF. The Wolfram parser and Import JSON accept CRLF; the only multi-line string literals are the CSS blocks at demo_html.wl:1568 and demo_outreach.wl:495, where \r is harmless. Generated CSV/Markdown are written with \n. Low risk.

## Part 4: fonts, graphics and export
- Fonts named: bayes/src/animate.wl:167 FontFamily "Courier" (Windows maps to Courier New; Linux substitutes, usually Liberation Mono/DejaVu); lagrange/src/animate.wl:20 "Helvetica" and tools/src/video_pipeline.wl:186 "Helvetica" (not on Windows or most Linux; substituted, e.g. Arial or Liberation Sans). Every other Graphics/Style call uses Wolfram's default font. DEGRADE (layout may shift slightly).
- Export formats in use: WAV (47 call sites in 22 files, Export[path, Sound[SampledSoundList[...]], "WAV"]; stem-core ExportAudioBuffer and RenderAudio), GIF (stem-core ExportGIF, every app), PNG (37 sites, e.g. henon, waves, hydrogen/src/animate.wl:110 by extension), CSV (stem-core ExportCSV), Text (demo scripts), MP4 (tools/ only). No PDF, SVG or MP3.
- WAV through SampledSoundList: works headless on the Mac; documented as headless-safe on all platforms (root AGENTS.md) but not tested on Windows/Linux (VM).
- GIF and PNG of Graphics need Wolfram's rasteriser (the front-end renderer, started headless by the kernel). Works on the Mac. On Linux, Wolfram Engine's headless rendering needs system libraries (fontconfig, X/GL client libraries) that minimal or server installs may lack; if rendering fails, every app's GIF and PNG fails. Highest-risk item; VM.
- GIF pixel size: measured on the Mac, GIFs exported without an explicit resolution come out at exactly 2x the requested ImageSize (dynamical sweep 600x420 -> 1200x840, iterate 600x380 -> 1200x760, pendulum base width 480 -> 960). dynamical lyapunov/divergence rasterise explicitly at 144 dpi (1440x1200), independent of the platform. The 2x is consistent with the macOS front end's Retina backing scale; on Windows and Linux it is expected to be 1x (VM). Affects pixel size and file size only, not frame timing or sync.
- tools/ MP4 export via VideoCombine: Mac-tested only (Part 1).

## Part 5: shell and helper scripts
- Tracked non-Wolfram scripts: only pendulum/tests/verify_animation_frames.py (frame-clipping check for pendulum GIFs; verification only; python3 + numpy + Pillow). Windows: `py pendulum\tests\verify_animation_frames.py` after `py -m pip install numpy pillow`; Linux: as documented.
- No .sh scripts are tracked. The bash loops and Python measurement scripts used for the project's VERIFICATION_*.md reports (WAV/GIF durations, pyloudnorm) lived in session scratchpads and are not in the repo, so that verification cannot be repeated on a VM as-is. VERIFY.
- Needed to run the apps: nothing but wolframscript (plus curl for asteroids, espeak-ng on Linux for narration, network for asteroids/cosmology planck).
- README run commands (README.md:121-300) use `wolframscript -file app/main.wl -- --key=value`. Linux bash: work verbatim. Windows PowerShell: forward slashes are accepted; `#` starts a comment as in bash; whether PowerShell passes the bare `--` through to the native wolframscript.exe has varied between PowerShell versions (VM; the apps also accept the arguments without `--` only if wolframscript does not consume them). Windows cmd: `#` is not a comment, so the trailing `# …` text on many README lines is passed to the app as extra arguments.
- README.md:304-371 playback lines are `afplay …` (macOS only); README.md:373-379 show the Linux (`aplay`) and Windows PowerShell (`Start-Process wmplayer`, backslash paths) form for two files and say to replace afplay for the rest, so the other lines need hand editing on Windows and Linux.
- `wolframscript -file <app>/main.wl -- --config-dump | python3 -m json.tool` (README.md:1039, AGENTS.md:154, docs/APPS.md:61, stem-core/ACCESSIBILITY.md:83-88): Windows usually has `py` rather than `python3`.
- `STEM_SPEAK=1 wolframscript -file …` (root AGENTS.md, app READMEs): bash syntax; PowerShell needs `$env:STEM_SPEAK = "1"; wolframscript …`, cmd needs `set STEM_SPEAK=1`.
- README.md:4 badge "Wolfram Language 13+": code uses FrameListVideo/VideoCombine (tools), RecurrenceFilter, MinFilter, Compile; developed on 15.0.1; the minimum version is untested.

## Part 7: smoke test design (tools/smoke_test.wl, not written yet)
- One command on any platform: `wolframscript -file tools/smoke_test.wl` (optional `-- --quick` for 1 mode per app, `-- --out=<path>`). Writes smoke_test_<SystemID>_<date>.txt next to the repo root (path from DirectoryName[$InputFileName]); copy that one file back to the Mac.
- App list: built from every <app>/main.wl in the repo (FileNames), default mode only, plus demo.wl last; each app's default mode comes from its config.json, so nothing is hard-coded.
- Isolation: run each app in-process like demo.wl (Block[{$ScriptCommandLine = {"main.wl", "--"}, $projectRoot, ...}, Get[main.wl]]) to avoid the licence problem of child kernels; wrap in Check/CheckAbort/TimeConstrained (e.g. 600 s) so a failure, a message or a hang is recorded and the loop continues; capture each app's console into a temporary file with $Output (portable, no /dev/null) and keep its last lines and every `::` message.
- Outputs: list files in <app>/output newer than the run start; for each WAV read duration (stem-core WAVDuration), integrated loudness (stem-core MeasureIntegratedLoudness, BS.1770) and peak; for each GIF frame count and duration (GIFFrameDelays) and pixel size; note whether the WAV starts with speech (an intro of at least 1 s before a 0.4 s pause) to detect missing narration.
- Environment block at the top of the report: $Version, $SystemID, $OperatingSystem, $CharacterEncoding, $SystemCharacterEncoding, whether SpeechSynthesize["Test."] returns Audio, whether say/espeak-ng/espeak/powershell/curl run, a probe line with é, —, λ written to the report and printed, and the pixel size of a test Graphics exported to GIF with ImageSize 100.
- Report format: plain text, UTF-8 written with explicit CharacterEncoding, one line per app: `app | mode | status (OK/FAIL/TIMEOUT/MESSAGES) | seconds | WAV s | LUFS | peak dBFS | GIF s | GIF-WAV s | GIF px | intro yes/no | first message`, then demo.wl's result line, then the messages in full below the table.
- Exit code 0 if every app produced a WAV, else 1, so the same script can serve a CI later.
